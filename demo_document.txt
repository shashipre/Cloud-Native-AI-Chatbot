Project Overview: Cloud-Native AI Chatbot
===========================================

Architecture Summary
--------------------
This system is a multi-user, cloud-deployed Retrieval-Augmented Generation (RAG) chatbot. 
It uses FastAPI as the backend, React as the frontend, and PostgreSQL with pgvector for 
vector similarity search. Documents are stored in AWS S3, and Google Gemini provides 
both embedding generation and conversational AI capabilities.

Key Technical Decisions
-----------------------
1. We chose pgvector over Pinecone because it eliminates the need for a separate vector 
   database service. All data (relational + vector) lives in a single PostgreSQL instance, 
   simplifying infrastructure and reducing costs.

2. The embedding dimension is 768, generated by Google's gemini-embedding-001 model. 
   This provides an excellent balance between retrieval quality and storage efficiency.

3. Authentication uses JWT tokens with bcrypt password hashing. Each token expires after 
   24 hours and contains the user ID, enabling stateless session management.

4. Document chunking uses a sliding window of 2000 characters with 200 character overlap 
   to ensure no important context is lost at chunk boundaries.

RAG Pipeline Details
--------------------
When a user uploads a document:
- The file is stored in AWS S3 under a user-specific path
- Text is extracted using PyMuPDF (for PDFs) or python-docx (for DOCX files)
- The text is split into overlapping chunks of approximately 500 tokens
- Each chunk is converted to a 768-dimensional vector embedding
- Chunks and embeddings are stored in PostgreSQL using the pgvector extension

When a user asks a question:
- The question is embedded using the same model (with retrieval_query task type)
- A cosine similarity search finds the top 3 most relevant chunks
- These chunks are assembled into a context prompt
- The LLM generates an answer grounded exclusively in the retrieved context
- Source citations are returned alongside the answer

Performance Metrics
-------------------
- Average embedding generation time: ~200ms per chunk
- Average query-to-answer latency: ~2 seconds
- Vector search is scoped to the authenticated user's documents only
- Cascade deletes ensure data consistency when documents are removed
